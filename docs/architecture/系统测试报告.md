## 3. 模型层测试

### 3.1 测试文件

| 文件 | 主要覆盖 |
|:---|:---|
| `test_agent_runner_input_order.py` | 图片进入 LangGraph 的顺序、影像服务不可用时拒绝、完整报告替换流式片段 |
| `test_code_assist_modes.py` | 四种代码辅助模式、模式标记传递、专用 Prompt 互斥 |
| `test_intent_input_guard.py` | 功能级输入守卫、任务包装防绕过、代码请求放宽边界、无关内容拒绝 |
| `test_qwen_models.py` | Qwen 默认配置、Embedding 维度、向量/BM25 降级、共享记忆集合、视觉消息 |
| `test_reasoning_trace.py` | 检索来源、可审计节点摘要、完整报告替换事件 |

### 3.2 关键回归场景

- 代码辅助选择 `complete`、`diagnose`、`optimize`、`explain` 后，模式能从路由传到报告节点。
- 代码请求附有真实代码时，即使描述只有“帮我看看”，也不会被输入守卫误拦截。
- 选择代码讲解但询问天气时仍会被拒绝。
- 向量检索初始化或查询失败后仍可使用 BM25。
- Qwen Embedding 返回错误维度时立即失败，避免污染向量库。
- `replace` 事件覆盖此前 Token，避免最终内容重复。

### 3.3 警告

`tests/test_qwen_models.py` 触发 10 次 `PydanticDeprecatedSince211`，来源为当前 ChromaDB 依赖访问实例 `model_fields`。这是依赖级兼容性风险，应跟踪 ChromaDB/Pydantic 后续版本。

## 7. 当前未覆盖范围

| 风险 | 当前缺口 | 建议 |
|:---|:---|:---|
| 登录与注册全链路 | 无数据库容器集成测试 | 使用 Testcontainers 覆盖 MySQL、Redis 和拦截器 |
| 64 个 Java 端点 | 仅少量服务/工具单测 | 增加 MockMvc/WebTestClient 契约测试 |
| 真实模型响应质量 | 单测主要使用 Mock | 建立受控评测集并保存模型、Prompt、知识库版本 |
| 浏览器 UI | 无 Playwright/E2E 套件 | 覆盖登录、画像、资源、路径、评估和代码辅助主流程 |
| SSE 重连 | 有流合并测试，无断网恢复集成测试 | 注入连接中断并验证 `Last-Event-ID` 回放 |
| 并发性能 | 本次未执行压测 | 使用固定环境和 Locust/k6，保存原始结果 |
| 安全 | 无系统化越权和上传攻击测试 | 增加接口授权、文件白名单和模型路由暴露检查 |
| Office 文档 | 不随代码自动验证 | 发布前依据权威 Markdown 人工复核 |

## 8. 关于历史指标

旧版文档包含并发成功率、P95、RAG 精度和多智能体满意度等数字，但仓库中没有与这些数字一一对应的原始结果、硬件环境和执行脚本。本版不将其作为当前测试结论。

后续性能报告至少应包含：

1. Git 提交、配置和模型名称。
2. CPU、内存、网络、数据库和外部模型配额。
3. 数据集、并发模型、预热方式和持续时间。
4. 原始结果文件与计算脚本。
5. 成功率、首 Token、总耗时、P50/P95/P99 和错误分类。
