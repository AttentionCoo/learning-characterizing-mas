# LearnAgent 需求规格说明书

> **版本**：V2.0
> **基线类型**：当前实现（As-Built）
> **核对日期**：2026-07-29
> **适用范围**：前端、Java 后端、Python 模型服务及 Docker Compose 部署

本文档根据仓库当前代码整理，用于开发、联调和验收。接口字段与路径以
[接口文档](../api/LearnAgent系统接口文档.md)为准；架构取舍以
[系统设计说明书](系统设计说明书.md)为准。

## 1. 目标与范围

LearnAgent 面向高等教育个性化学习场景，以脑卒中医学教育为示范领域，提供：

- 对话式学生画像构建与持续更新；
- 多智能体学习资源生成、智能辅导和学习路径规划；
- 学习行为记录与效果评估；
- 代码执行及代码补全、错误诊断、优化建议、代码讲解；
- 医学影像分析、病例分析和 OCR/DICOM 工具；
- SSE 流式输出、对话持久化和短时断线续传。

当前系统不提供独立的 `/api/documents/**` REST 接口。医学文献由模型层 RAG
读取，资源文档链接由现有业务服务按需生成。

## 4. 非功能需求

### 4.1 安全

| 编号 | 要求 | 当前验收口径 |
|:---|:---|:---|
| NFR-SEC-01 | 密码安全 | 数据库不得保存新注册用户的明文密码 |
| NFR-SEC-02 | JWT 鉴权 | 除登录、注册、上传和静态上传文件外，业务接口需有效 Token |
| NFR-SEC-03 | 模型边界 | `/model/get_result` 校验共享 JWT；其他模型专用路由只允许内网调用 |
| NFR-SEC-04 | XSS 防护 | AI Markdown 渲染前使用 DOMPurify 清理 |
| NFR-SEC-05 | 上传约束 | 仅允许配置的图片扩展名，单文件不超过 5 MB |
| NFR-SEC-06 | 密钥管理 | API Key、数据库密码、OSS 密钥和 JWT 密钥只通过环境变量注入 |

上传接口目前属于公开路径，这是现有兼容行为，不应扩展为任意文件上传能力。

### 4.2 可用性与降级

| 编号 | 要求 | 当前验收口径 |
|:---|:---|:---|
| NFR-AVL-01 | RAG 召回降级 | 向量检索失败时保留 BM25 召回 |
| NFR-AVL-02 | 精排降级 | Qwen Rerank 失败时使用 RRF 融合结果 |
| NFR-AVL-03 | 流式错误 | 失败时输出结构化 `error`，随后正常结束事件流 |
| NFR-AVL-04 | 短时续传 | 单实例事件缓存默认保留五分钟 |
| NFR-AVL-05 | 服务健康 | Docker Compose 通过健康检查约束依赖启动顺序 |

### 4.3 性能与容量

当前自动化测试未包含正式负载测试，因此不声明固定并发数、首 Token 延迟或月度可用率。
发布前应在目标硬件和实际模型配额下独立验证：

- SSE 并发连接数与代理超时；
- 首事件、首 Token 和完整响应耗时；
- MySQL、Redis 连接池和线程池饱和点；
- 大图片、多图片和长代码输入的内存占用；
- Qwen API 限流与重试行为。

## 6. 数据需求

当前数据库包含 14 张表：

`user`、`student_profile`、`talk`、`cont`、`learning_resource`、
`learning_path`、`learning_path_step`、`step_resource`、`learning_behavior`、
`evaluation_report`、`patient`、`health_data`、`ai_opinion`、`learning_material`。

关键约束：

1. 画像与用户为一对一关系，更新时版本号递增；
2. 对话必须归属当前用户，消息必须归属一个对话；
3. 不同业务对话类型不得交叉复用；
4. 学习路径删除时级联清理步骤和步骤资源关联；
5. 演示 SQL 中含样例账号和医学文本，生产环境必须拆分结构与种子数据。

详见[数据库设计手册](数据库设计手册.md)。

## 7. 关键业务状态

### 7.1 SSE 生命周期

```text
init -> thinking/chunk/replace/structured events -> done
                                      \-> error -> done
```

`replace` 表示用新内容替换当前累计文本，客户端不得按普通增量重复拼接。

### 7.2 对话创建规则

```text
请求携带 talkId
  -> 属于当前用户且类型匹配：复用
  -> 缺失、无效、越权或类型不匹配：创建当前业务类型的新对话
```

画像提取是画像对话结束后的派生操作，不进入上述“创建对话”分支。

### 7.3 RAG 流程

```text
向量召回(最多20) + BM25召回(最多20)
  -> RRF(k=60，保留20)
  -> Qwen Rerank(最终3)
  -> 证据合成
```

检索缓存以 `MD5(query + top_k)` 为键，位于 Python 进程内，默认 TTL 为 300 秒。

## 8. 验收基线

| 范围 | 命令 | 当前结果 |
|:---|:---|:---|
| 模型层 | `cd model && python -m pytest -q` | 93 通过 |
| 前端 | `cd frontend && npm test` | 16 通过 |
| 后端 | `cd backend/server && mvn test` | 9 通过，1 跳过 |

验收还应覆盖以下人工链路：

1. 登录后分别创建画像、资源、辅导、路径、评估和代码辅助对话；
2. 生成画像时确认没有新增第二条画像对话；
3. 四种代码辅助模式均产生对应内容，且只选择代码仍可输出；
4. 断开 SSE 后携带 `Last-Event-ID` 恢复同一对话；
5. 非医学图片、对抗性提示和无 Qwen Key 场景均被医学门控拒绝；
6. 向量检索或 Rerank 失败时仍能得到受控降级结果。

## 9. 已知边界与后续需求

- 独立文档管理 REST 接口尚未实现；
- 学习路径调整目前返回兼容结构，尚未执行真实路径重排；
- SSE 与模型任务缓存均为进程内存，多实例部署前需要共享存储；
- 模型专用路由的鉴权不完全一致，必须保持网络隔离；
- 正式性能指标需要在目标部署环境完成压测后再写入验收标准；
- 数据库初始化脚本同时包含结构和演示数据，生产发布应迁移到版本化脚本。
